# 构想引擎设计语言与布局

本文件约束桌面应用的界面设计。实现时以本文件为准，变更须先改这里。原型见 `docs/design/mockup.html`。

## 用户与任务

| 用户 | 场景 | 心理状态 | 界面必须回答 |
| --- | --- | --- | --- |
| 机械类学生（首要） | 课程设计：任务书 → 方案 → 传动零件 → 轴系 → 箱体 → 图纸 → 说明书 → 答辩 | 怕错、怕被问"这个数从哪来"、对软件不熟、时间紧 | 我做到哪一步了？哪里不安全？这个数怎么来的？改了会影响什么？ |
| 指导教师 / 评阅 | 抽查数值、核对来源 | 怀疑、需要快速定位 | 每个结论的依据和裕度 |
| 工程师（后续） | 已有零件尺寸修订、出图 | 关心原件安全、可撤销、可追溯 | 原件是否被动过？当前在哪个工作副本？操作是否真的成功？ |

学生的心智模型是**课程设计指导书的章节顺序**，不是"原生/计算/任务"这类软件模块。工程师的心智模型是**对象（零件、图纸）与修订**。界面按这两种模型组织，软件内部模块只出现在设置和诊断里。

## 依据

- NN/g 复杂应用：信息未按领域专家工作流组织是主要复杂度来源；用户常停在"够用"水平，应在做中学。→ 导航按设计流程分阶段；入口就地出现，不靠记菜单。
- CAD 认知负荷研究：难点在把意图翻译成命令序列的规划负担。→ 命令面板（⌘K）用任务语言搜索；选中对象后只显示与它相关的操作。
- Figma UI3：浮动面板让重度用户觉得画布变小、间隙分散注意，最终改回贴边、可调宽、可折叠面板。→ 面板一律贴边，可折叠，不浮动。
- Linear：倒 L 外框承载全局导航，主区只放内容；减少边框，不为未赢得注意的功能抢注意。
- Apple HIG / Fluent 2：侧栏默认显示且可隐藏；检查器显示当前选择而非导航；专业工具用紧凑密度。
- 微软人机 AI 交互 18 条：说明系统能做到什么程度、出错频率；传达操作后果；可全局控制；变化要通知。→ 助手提案以"差异 + 影响 + 来源"呈现，写入前确认，结果带回执。

## 原则

1. **工作对象居中。** 中间永远是当前对象（参数表、三维、图纸），其余都是它的上下文。
2. **按设计流程组织。** 一级导航是设计阶段；每阶段带状态（未开始 / 已算 / 有问题 / 已出图）。
3. **每个数可追溯。** 数值旁的来源标记：输入、标准、公式、近似、助手提议。点开在检查器看公式、代入值和标准号。
4. **展示裕度，不只展示通过。** 校核项显示利用率条（实际 / 许用）。92% 和 12% 都是"通过"，但对学生和评阅意义完全不同。
5. **后果先于操作。** 任何修改先显示影响范围（哪些校核、图纸、说明书段落会变），再确认。
6. **状态始终可见。** 底部修订轴显示当前修订、原件保护、未确认操作；顶部显示校核汇总。
7. **克制。** 颜色只表达状态和焦点；装饰性元素为零；动画只用于状态变化。

## 布局

```
┌─────────────┬──────────────────────────────────────┬───────────────┐
│ 工程         │ 阶段标题   [参数|三维|图纸]   校核汇总 │ 检查器         │
│ 设计流程     ├──────────────────────────────────────┤  选中值的公式、 │
│  ● 任务书    │                                      │  代入、来源、   │
│  ● 总体方案  │          当前阶段的工作对象            │  被谁引用       │
│  ◐ 传动零件  │                                      ├───────────────┤
│  ○ 轴系      │                                      │ 工程助手        │
│  …          │                                      │  以当前选择为   │
│ 原生模型     │                                      │  上下文         │
│ 文件（折叠） ├──────────────────────────────────────┴───────────────┤
│ 设置         │ 修订轴：r1 ─ r2 ─ ●r3(当前)   原件受保护   0 个待确认操作  │
└─────────────┴───────────────────────────────────────────────────────┘
```

- 左侧栏 232 px，可隐藏（⌘\）。
- 右侧 320 px，检查器在上、助手在下，分隔可拖；两者都可折叠（⌘I、⌘J）。助手以当前选择为上下文，不再与检查器互斥。
- 底部修订轴 32 px，展开后显示操作记录与回执，替代原"任务"页。
- ⌘K 命令面板：阶段、文件、对象、命令统一搜索。

## 视觉规格：算稿纸

取自课程设计计算纸的淡绿底和钢笔蓝墨水。实现见 `desktop/src/style.css` 的 `:root`，原型的三个比较方向保留在 `docs/design/mockup.html`。

- 色彩：外框 `#e6ebe3`，工作纸面 `#f4f7f2`（带 20 px 淡格），选中/弹层 `#fbfcfa`，条槽 `#dde4da`；墨色 `#1d2824 / #4a5852 / #7b8882`。唯一强调色钢笔蓝 `#23508a`，只用于焦点、选中和主操作。状态色与强调色分开：通过 `#2f7a57`、临界（利用率 ≥ 85%）`#b0731a`、未通过 `#b23b2a`。
- 层次靠纸面与外框的明度差和细线，不靠卡片；阴影只用于弹层和图纸。
- 字体：中文用系统字体（苹方 / 微软雅黑）；所有数值用随应用打包的 IBM Plex Mono，保证列对齐；单位降一级灰色。
- 来源标记：标（标准）、式（公式）、近（近似）、入（输入），9.5 px 细框小标。
- 利用率：≤ 型为实际 / 许用，≥ 型为要求 / 实际，由 `gongke_core.design.Check.utilization` 给出；条上 85% 处画刻线。
- 间距 4 px 网格；阶段标题 22 px / 700；数值 16 px / 500；正文 13 px。
- 动效：利用率条与裕度谱生长 0.5–0.6 s，检查器内容 0.22 s 淡入；系统“减少动态效果”时全部关闭。
